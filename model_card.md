# Model Card — Random Forest для прогнозирования продаж

Структура основана на [Google Model Cards for Model Reporting](https://research.google/pubs/model-cards-for-model-reporting/).
Проект: Time_series_forecasting, пакет forecasting, версия пакета 0.1.0. Статус: учебная реализация, подготовленная к пакетному применению; промышленное внедрение не подтверждено.

## 1. Cведения о модели

Глобальная регрессионная модель RandomForestRegressor (scikit-learn) в обвязке MLForecast. Один лес обучается на наблюдениях нескольких рядов. Многошаговый прогноз рекурсивный: предсказания используются при построении последующих лагов.

| Параметр | Значение |
|---|---|
| n_estimators | 200 |
| max_depth | 15 |
| min_samples_leaf | 2 |
| random_state | 42 |
| n_jobs | -1 |
| Частота | D |
| Лаги | 1, 7, 14, 28, 90 |
| RollingMean на лаге 1 | 7, 28 |
| Календарные признаки | dayofweek, month, year |
| Горизонт по умолчанию | 90 дней |

Источник: [train.py](src/forecasting/train.py). Python 3.12, зависимости определены в [pyproject.toml](pyproject.toml). Артефакт — обученный MLForecast, сериализованный joblib; версия пакета не является версией весов. Отдельный владелец эксплуатации и лицензия модели не определены.

## 2. Назначение

Прогноз ежедневного количества продаж каждой пары магазин–товар. ML позволяет учитывать нелинейные зависимости между историей продаж и календарём; полезность следует проверять относительно простых сезонных методов. Предполагаемый пользователь — аналитик запасов. Прогноз служит одним из входов планирования пополнения, но не готовым заказом. Остатки, сроки поставки и ограничения закупок необходимо учитывать отдельно. Интеграция с ERP и автоматические закупки не реализованы.

| Этап | Формат |
|---|---|
| Исходный CSV | store, item, date, sales |
| Подготовленная история | unique_id = store_item, ds = дата, y = продажи |
| Прогноз | unique_id, ds, RandomForestRegressor |
| Пакетное применение | сохранённая модель + положительный горизонт; CSV по запросу |

[data.py](src/forecasting/data.py) проверяет обязательные колонки, пропуски, даты, числовой тип продаж и дубликаты ключей. Непрерывность календаря, неотрицательность и конечность исходных продаж требуют дополнительных проверок. [inference.py](src/forecasting/inference.py) использует сохранённую историю, не принимает новые продажи и не переобучает модель.

## 3. Факторы качества

Магазин, товар, сезон, уровень продаж, длина истории, изменение ассортимента, акции и дефицит могут влиять на качество. Цены, акции, остатки и внешние признаки не передаются. Отдельная оценка по группам и устойчивость к дрейфу в production-коде не подтверждены.

## 4. Mетрики

| Метрика | Формула и смысл |
|---|---|
| MAE | mean(abs(y - prediction)); средняя абсолютная ошибка в единицах продаж |
| RMSE | sqrt(mean((y - prediction)^2)); сильнее штрафует крупные ошибки |
| MAPE | 100 * mean(abs((y - prediction)/y)) для y != 0 |

Меньше — лучше. Усреднение по наблюдениям. При полностью нулевом факте MAPE = NaN; это не успешная оценка. MAE/RMSE учитывают нули. [evaluate.py](src/forecasting/evaluate.py) требует точного совпадения ключей, отсутствия дубликатов и конечных значений.

## 5. Данные оценки

Исследовательский датасет Store Item Demand Forecasting: 913 000 строк, 10 магазинов, 50 товаров, 500 ежедневных рядов, 2013–2017. См. [исходное исследование](README.md). Текущий [pipeline.py](src/forecasting/pipeline.py) удерживает последние 90 наблюдений каждого ряда при стандартном горизонте; отдельной Validation в этом модуле нет. Для полной непрерывной панели это последние 90 календарных дней. Для иных данных общие календарные границы и полноту необходимо проверить отдельно. max_series ограничивает число рядов для технических запусков.

## 6. Данные обучения

В оценочном pipeline используются наблюдения до отложенного периода. MLForecast формирует лаги и скользящие средние из прошлых продаж. Код требует более 118 обучающих строк на представленный ряд; это техническая проверка, не гарантия качества. Необходимо дополнительно исключать ряды, полностью попавшие в Test. [final_train.py](src/forecasting/final_train.py) отдельно обучает модель на всей доступной истории для будущего прогноза; метрики holdout нельзя считать независимой оценкой этого нового артефакта.

## 7. Результаты

В исходном исследовании Random Forest показала MAE 6.372 на Test. Это исторический результат исследовательского эксперимента, не аттестация текущего артефакта. Для текущей конфигурации воспроизводимая команда:

```bash
poetry run python -m forecasting.pipeline --data data/train.csv --horizon 90
```

Pipeline выводит MAE, RMSE и MAPE. В карточке не утверждаются неподтверждённые метрики конкретной сохранённой версии. Для релиза следует сохранять состав рядов, даты, хеш данных, параметры и результаты отдельного запуска. Сравнение с baseline должно использовать одинаковые ключи и даты.

## 8. Риски

Занижение прогноза может привести к дефициту, завышение — к излишкам. Продажи не равны полному спросу при отсутствии товара. Входная схема не содержит персональных признаков покупателей, но аудит приватности и лицензии не проведён. Необходим контроль специалистом; экономический эффект не измерен.

## 9. Ограничения

Рекурсивный прогноз может накапливать ошибки; лес плохо экстраполирует ранее не наблюдавшиеся уровни продаж. Прогноз точечный и может быть дробным. Нет интервалов неопределённости, подтверждённой поддержки новых рядов без истории, автоматического мониторинга, реестра и деплоя. Joblib загружать только из доверенного источника в совместимом окружении. Для автоматического выпуска необходимы независимая оценка, проверка данных и утверждённые критерии допуска.
