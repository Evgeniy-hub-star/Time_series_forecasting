# Анализ и прогнозирование временного ряда продаж

## 1. Описание проекта

Цель работы — освоение инструментов анализа временных рядов в типичных прикладных задачах и модельных условиях, а также построение и сравнение различных методов прогнозирования.

В качестве исходных данных используется временной ряд продаж товаров в магазинах. Датасет доступен по ссылке: https://www.kaggle.com/competitions/demand-forecasting-kernels-only/data

Исходный датасет содержит около 913 000 наблюдений и следующие признаки:

- `store` — идентификатор магазина;
- `item` — идентификатор товара;
- `date` — дата наблюдения;
- `sales` — количество продаж.

Для каждой пары `store-item` формируется отдельный временной ряд.

Горизонт прогнозирования: HORIZON = 90 дней.

В работе реализованы четыре основных этапа:

1. подготовка и исследование данных;
2. анализ временных рядов;
3. построение и сравнение моделей прогнозирования;
4. автоматизация процесса прогнозирования.

---

# 2. Задача 1. Подготовка и исследование данных

## 2.1. Подготовка данных

На первом этапе выполнена загрузка и первичная проверка исходного набора данных.

Были исследованы:

- размер датасета;
- типы данных;
- наличие пропущенных значений;
- диапазон дат;
- количество магазинов;
- количество товаров;
- количество уникальных временных рядов;
- распределение объёма продаж.

Для работы с моделями прогнозирования данные были преобразованы к формату:

```text
unique_id | ds | y
```

где:

- `unique_id` — уникальный идентификатор временного ряда, сформированный из `store` и `item`;
- `ds` — дата;
- `y` — значение временного ряда.

Пример формирования идентификатора:

```python
result["unique_id"] = (
    result["store"].astype(str)
    + "_"
    + result["item"].astype(str)
)
```

## 2.2. Разбиение данных

Данные были разделены на три выборки:

- Train — обучение моделей;
- Validation — подбор и сравнение моделей;
- Test — финальная независимая оценка.

Горизонт Validation и Test составляет по 90 дней.

Такое разбиение позволяет не использовать тестовую выборку при выборе модели и получить более объективную оценку качества.

## 2.3. Разведочный анализ

В ходе EDA были исследованы:

- динамика продаж;
- распределение значений `sales`;
- различия между магазинами и товарами;
- временные зависимости;
- наличие сезонности и трендов;
- поведение отдельных временных рядов.

Анализ показал наличие выраженной временной структуры в данных, что делает применение методов прогнозирования временных рядов обоснованным.

# 3. Задача 2. Анализ временных рядов и выбор методов

Для прогнозирования были рассмотрены различные классы моделей.

Основными критериями сравнения являлись:

- **MAE** — средняя абсолютная ошибка;
- **RMSE** — корень из средней квадратичной ошибки;
- **MAPE** — средняя абсолютная процентная ошибка.

Чем меньше значение метрики, тем выше качество прогноза.

## 3.1. Выбор методов

В проекте использованы следующие подходы:

### Baseline

Baseline используется как простая точка отсчёта для оценки того, насколько сложные модели превосходят простой прогноз.

### Статистические методы

В рамках исследования рассматривались классические методы прогнозирования временных рядов, позволяющие учитывать тренд, сезонность и автокорреляционные зависимости.

### ML-модели

Были выбраны:

- Random Forest;
- XGBoost;
- LightGBM.

Эти методы позволяют использовать лаговые и другие производные признаки временного ряда и способны моделировать нелинейные зависимости.

### DL-модели

Для глубокого обучения использованы:

- N-BEATS;
- N-HITS;
- LSTM.

N-BEATS и N-HITS ориентированы непосредственно на прогнозирование временных рядов, а LSTM использует рекуррентную архитектуру для моделирования последовательностей.

# 5. Backtesting

Для дополнительной оценки устойчивости прогнозирования был выполнен backtesting модели N-BEATS на нескольких временных срезах.

Результаты:

|---|---:|---:|---:|

| **Среднее** | **6.148** | **7.965** | **13.774%** |

Средние показатели backtesting:

- MAE = 6.148;
- RMSE = 7.965;
- MAPE = 13.774%.

Результаты на разных временных срезах достаточно стабильны. Разброс метрик присутствует, однако модель сохраняет сопоставимый уровень качества на различных периодах.

Backtesting подтверждает, что полученное качество N-BEATS не связано только с одним конкретным временным интервалом.

# 7. Задача 4. Автоматизация процесса прогнозирования

Для автоматизации была сформирована последовательность обработки данных и построения прогноза.

Общий pipeline:

```text
Исходные данные
      ↓
Проверка и подготовка данных
      ↓
Формирование unique_id / ds / y
      ↓
Train / Validation / Test
      ↓
EDA и анализ временных рядов
      ↓
Обучение моделей
      ↓
Прогноз на 90 дней
      ↓
Расчёт MAE / RMSE / MAPE
      ↓
Сравнение моделей
      ↓
Выбор лучшей модели
      ↓
Финальное обучение
      ↓
Прогноз будущих 90 дней
      ↓
Сохранение результатов
```

Для подготовки данных используется единая функция:

```python
def prepare_forecast_format(data):
    result = data.copy()

    result["unique_id"] = (
        result["store"].astype(str)
        + "_"
        + result["item"].astype(str)
    )

    result = result.rename(
        columns={
            "date": "ds",
            "sales": "y"
        }
    )

    return (
        result[
            ["unique_id", "ds", "y"]
        ]
        .sort_values(["unique_id", "ds"])
        .reset_index(drop=True)
    )
```

Для оценки моделей используются три основные метрики:

```text
MAE
RMSE
MAPE
```

Это позволяет автоматически сравнивать различные модели по единому набору критериев.
