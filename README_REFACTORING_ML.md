# Time Series Forecasting — рефакторинг для production

## 1. Назначение документа

Данный документ описывает рефакторинг исходного исследовательского проекта прогнозирования розничных продаж и подготовку его к использованию в production-среде. Исходный [`README.md`](README.md) остаётся без изменений: в нём представлены исследовательская часть, сравнение моделей и выводы. Здесь описаны модульная реализация на Python, воспроизводимый запуск, автоматические проверки, сохранение моделей и построение прогнозов.

**Текущий статус:** прототип, подготовленный к дальнейшему внедрению в production, с автоматическими тестами и CI. Это ещё не развёрнутый промышленный сервис.

## 2. Проект и данные

Исходный датасет содержит ежедневные продажи по магазинам и товарам. Входной CSV должен содержать следующие столбцы:

| Столбец | Описание |
| --- | --- |
| `store` | Идентификатор магазина |
| `item` | Идентификатор товара |
| `date` | Дата наблюдения |
| `sales` | Количество продаж |

На этапе подготовки данные преобразуются в формат `MLForecast`: `unique_id` (идентификатор ряда «магазин–товар»), `ds` (дата), `y` (целевая переменная). Горизонт прогнозирования по умолчанию — **90 дней**.

В модульном pipeline используется **Random Forest Regressor**. Другие ML- и DL-модели, исследованные в ноутбуках исходного проекта, автоматически в этот pipeline не включены.

## 3. Архитектура проекта

```text
Time_series_forecasting/
├── .github/
│   └── workflows/
│       └── ci.yml
├── src/
│   └── forecasting/

│       ├── train.py          # Создание и обучение модели
│       ├── predict.py        # Получение прогноза
│       ├── evaluate.py       # Расчёт метрик качества
│       ├── pipeline.py       # Обучение и оценка на тестовом периоде
│       ├── model_io.py       # Сохранение и загрузка модели
│       ├── inference.py      # Прогноз по сохранённой модели
│       └── final_train.py    # Финальное обучение на всей истории
├── tests/                    # Автоматические тесты
├── pyproject.toml            # Зависимости и конфигурация
├── poetry.lock               # Зафиксированные версии зависимостей (если есть)
├── .pre-commit-config.yaml   # Git-хуки
├── .gitignore

```

Обученные модели и результаты прогнозирования сохраняются локально в `models/` и `predictions/`. Обе папки исключены из Git через `.gitignore`.

### Назначение модулей

| Модуль | Ответственность |
| --- | --- |
| `data.py` | Преобразование исходных данных в `unique_id`, `ds`, `y` |
| `train.py` | Создание и обучение модели `MLForecast` с Random Forest |
| `predict.py` | Формирование прогноза на заданный горизонт |
| `evaluate.py` | Расчёт MAE, RMSE и MAPE |
| `pipeline.py` | Выделение тестового периода, обучение, прогноз, оценка и необязательное сохранение модели |
| `model_io.py` | Сериализация и загрузка объектов `MLForecast` с помощью `joblib` |
| `final_train.py` | Обучение на всей доступной истории и сохранение финальной модели |
| `inference.py` | Загрузка модели и экспорт прогноза в CSV |

## 4. Подготовка окружения

Рефакторинг выполнялся с использованием **Python 3.12.9** и **Poetry**. Из корня репозитория при наличии Python 3.12 выполните:

```powershell
poetry install
```

Команды запускаются через `poetry run`, чтобы использовать виртуальное окружение проекта. В примерах ниже предполагается, что исходные данные находятся в `data/train.csv`. Если файла нет в локальной копии проекта, его необходимо предоставить отдельно.

## 5. Основные сценарии запуска

Все команды выполняются из корня репозитория.

### 5.1. Обучение и оценка качества на отложенном периоде

```powershell
poetry run python -m forecasting.pipeline --data data/train.csv --horizon 90 --max-series 2 --model-path models/random_forest.joblib
```

Команда выполняет следующие действия:

1. Загружает и подготавливает исходные данные.
2. Выделяет последние 90 наблюдений каждого выбранного ряда для тестирования.
3. Обучает модель на более ранних наблюдениях.
4. Строит прогноз на тестовый период и рассчитывает MAE, RMSE и MAPE.
5. При наличии `--model-path` сохраняет **модель, обученную на тренировочной части**.

Параметр `--max-series 2` позволяет быстро проверить работу на двух рядах. Для использования всех рядов его нужно убрать. В этом режиме `--model-path` необязателен.

**Важно:** модель, сохранённая из `pipeline.py`, обучена без тестового периода. Её прогноз начинается после конца тренировочной части, то есть относится к историческому тестовому интервалу, а не к датам после последнего наблюдения полного датасета.

### 5.2. Финальное обучение на всей доступной истории

```powershell
poetry run python -m forecasting.final_train --data data/train.csv --model-path models/random_forest_final.joblib --max-series 2
```

В отличие от оценочного pipeline, `final_train.py` не выделяет тестовую выборку. Модель обучается на всей доступной истории выбранных рядов. Для обучения на всех рядах уберите `--max-series 2`.

Качество модели следует оценивать по ранее полученным результатам на отложенной выборке. Метрики на данных, использованных для финального обучения, нельзя выдавать за независимую тестовую оценку.

### 5.3. Прогнозирование без повторного обучения

```powershell
poetry run python -m forecasting.inference --model-path models/random_forest_final.joblib --horizon 90 --output predictions/final_forecast.csv
```

Команда загружает сохранённую модель, строит прогноз на 90 дней после её обучающей истории и записывает результат в CSV. Файл содержит идентификаторы рядов, даты и прогнозные значения. Для двух рядов и горизонта 90 дней получается **180 строк**.

Сохранённая модель `MLForecast` содержит состояние и историю, необходимые для такого прогнозирования. Команда `inference` не загружает новый исходный CSV и не переобучает модель. Для учёта новых наблюдений потребуется отдельный механизм обновления или переобучения модели; сейчас он не реализован.

## 6. Сохранение и загрузка модели

Модуль `model_io.py` предоставляет функции `save_model()` и `load_model()` на базе `joblib`. При загрузке проверяется, что восстановленный объект относится к `MLForecast`; отсутствие файла сопровождается понятной ошибкой. Тесты подтверждают, что прогноз обученной модели не меняется после сохранения и загрузки.

**Безопасность:** загружайте файлы `.joblib` только из доверенных источников. Форматы на базе Python pickle могут выполнять произвольный код при десериализации. Совместимость сохранённых моделей зависит в том числе от версий библиотек; для воспроизведения окружения используйте конфигурацию зависимостей проекта.

## 7. Тестирование и контроль качества кода

Для автоматических тестов используется `pytest`. Проверяются подготовка данных, обучение, прогнозирование, расчёт метрик, работа pipeline, сохранение и загрузка модели, inference и финальное обучение. В частности, проверяется, что прогноз финальной модели начинается после последней даты обучающей истории.

```powershell
poetry run pytest -v
poetry run ruff check src tests
poetry run ruff format --check src tests
poetry run pre-commit run --all-files
```

В ходе рефакторинга набор достиг **26 успешно проходящих тестов**. Их количество может изменяться при дальнейшем развитии проекта.

В `pre-commit` настроены Ruff (линтинг и форматирование), проверки YAML/TOML, завершающих переводов строк, пробелов в конце строк и маркеров конфликтов слияния. Некоторые хуки автоматически исправляют файлы; после этого проверки нужно повторить, а изменённые файлы заново добавить в Git перед коммитом.

## 8. Непрерывная интеграция (CI)

Workflow GitHub Actions `.github/workflows/ci.yml` запускается при `push` и создании/обновлении pull request. Он использует Ubuntu и Python 3.12, устанавливает зависимости через Poetry, затем запускает Ruff, проверку форматирования и `pytest`.

Работоспособность CI подтверждена успешными запусками в ветке `refactor/production`. CI проверяет код и тесты, но **не развёртывает модель** и не запускает полное обучение на всём датасете.

## 9. Ограничения и правила корректной оценки

- **Оценка и финальное обучение разделены.** Для независимой оценки используется отложенный период; для будущего прогноза модель отдельно обучается на всей истории.
- **Горизонт:** по умолчанию 90 дней; там, где поддерживается, можно указать другое положительное значение.
- **Длина ряда:** текущие проверки требуют более 118 наблюдений на ряд в тренировочной части оценочного pipeline и более 118 наблюдений на ряд для финального обучения.
- **Ограничение числа рядов:** `--max-series` полезен для быстрых локальных проверок, но такая подвыборка не является случайной или гарантированно репрезентативной.
- **Артефакты:** папки `models/` и `predictions/` предназначены для локальных результатов и не версионируются в Git.
- **Метрики:** MAE, RMSE и MAPE рассчитываются на исторической отложенной выборке, а не по будущим прогнозам финальной модели.

## 10. Что ещё требуется для полноценного production

Реализован воспроизводимый CLI-процесс с тестами и CI, но для промышленной эксплуатации дополнительно понадобятся:

1. Структурированное логирование, управление конфигурацией и понятная обработка ошибок.
2. Проверки схемы входных данных, качества данных и защиты от утечек информации из будущего.
3. Версионирование моделей, метаданные обучающих запусков и доверенное хранилище артефактов.
4. Мониторинг качества прогнозов, дрейфа данных, ошибок и потребления ресурсов.
5. Регламент автоматического переобучения, проверки новой модели, развёртывания и отката.
6. Упаковка приложения и среда исполнения, соответствующая выбранной платформе развёртывания.

## 11. Итоги рефакторинга

Исходный проект на Jupyter Notebook дополнен модульным Python-кодом с CLI, управлением зависимостями через Poetry, проверками Ruff и pre-commit, автоматическими тестами `pytest` и CI в GitHub Actions. Реализованы сохранение и загрузка обученной модели `MLForecast`, прогнозирование без повторного обучения и отдельное финальное обучение на всей доступной истории.

Исследовательская часть, сравнение алгоритмов и исходные выводы представлены в [`README.md`](README.md).
